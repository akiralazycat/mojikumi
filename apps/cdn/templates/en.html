The files you load Mojikumi from

This domain serves nothing but the files you put on a page. The guide to using them is on mojikumi.jp. The same files ship inside the mojikumi package on npm, if you would rather not load anything from a CDN.

Loading it

<script
  src="https://cdn.mojikumi.jp/{{channel}}/mojikumi.min.js"
  data-target=".entry-content"
  data-style="article"
></script>

The stylesheet is inside this file, so it is the only one to load. Give data-target the selector for your body text; leave it out and the usual containers are tried in turn.

data-style takes minimal, article or book. What each one sets is described in the guide.

What is served

PathContentsCache
/{{channel}}/mojikumi.min.js The browser build, stylesheet included 10 minutes
/{{channel}}/mojikumi.min.css The stylesheet on its own 10 minutes
/{{version}}/… The same build, pinned to a version 1 year, never rewritten

What /{{channel}}/ holds is replaced on every minor release. Fixes reach your site without you touching the tag, and so does everything else in that release. Incompatible changes go out as /v2/, leaving /{{channel}}/ where it is.

Pinning a version

A path with a version in it is never rewritten, so it can carry a hash of its contents. If the file does not match, the browser will not run it.

<script
  src="https://cdn.mojikumi.jp/{{version}}/mojikumi.min.js"
  integrity="{{integrityJs}}"
  crossorigin="anonymous"
  data-target=".entry-content"
></script>

For the stylesheet on its own, the hash is below. There is none for /{{channel}}/, whose contents are replaced.

{{integrityCss}}
